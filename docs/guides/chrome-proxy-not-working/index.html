Chrome 代理未生效？完整排查清单

“代理不能用”可能指网页打不开、出口 IP 没变化、认证失败或切换后仍由别的设置控制。先明确症状，再按层排查。

发布：2026-10-03技术指南 · 约 7 分钟
最快判断

先切换 Direct。Direct 也打不开，问题在基础网络；Direct 正常而代理失败，核对协议、主机、端口和授权；代理显示已启用但出口 IP 不变，检查白名单、System 模式、其他扩展和企业策略。

先把症状分成四类

症状优先检查
所有网页都超时代理端点是否在线、协议和端口、网络是否允许连接
出现 407 或认证弹窗用户名密码、IP 白名单、认证主机与端口
出口 IP 没变化是否启用了正确配置、目标是否命中绕过规则、是否使用 System
设置会自动跳回其他代理扩展、Chrome 企业策略、浏览器或系统管理软件

六层排查顺序

  1. 基础网络：切到 Direct 并访问两个无关站点。基础网络不通时不要继续改代理。
  2. 端点：从代理服务商控制台重新复制主机与端口，确认套餐仍有效且允许当前网络。
  3. 协议：HTTP、HTTPS、SOCKS4 和 SOCKS5 不是可互换的标签。按服务商给出的类型选择。
  4. 认证：遇到 407 时参考 代理认证排查。
  5. 路由：临时清空配置级和全局白名单，排除目标域名被直连。
  6. 控制权：在 chrome://extensions 只保留一个代理扩展；在 chrome://policy 查看是否有组织策略强制代理。

Direct、System 和自定义代理

Direct 是不经扩展代理的基准。System 让 Chrome 跟随操作系统配置，扩展不决定出口。只有启用 HTTP、HTTPS 或 SOCKS 配置时，ProxyFox 才把该端点应用到 Chrome。不要把“选择了配置”和“端点可访问”混为一谈。

正确使用连接测试

ProxyFox 的保存前测试会临时应用候选代理、访问您配置的测试地址、记录应用和网络耗时，然后恢复原设置。测试成功证明该时刻的端点可完成请求；它不保证所有网站可访问，也不持续监控代理质量。

证书错误不是“代理未生效”。如果 HTTPS 页面出现证书警告，代理或企业网关可能在进行 TLS 检查。应由网络管理员部署可信证书，不要绕过 Chrome 警告。

联系支持前收集证据

  • Chrome 版本和操作系统；
  • 代理协议、主机（可脱敏）与端口；
  • Direct 是否正常；
  • 具体错误码，例如 ERR_PROXY_CONNECTION_FAILED、ERR_TUNNEL_CONNECTION_FAILED 或 407；
  • 是否存在企业策略和其他代理扩展；
  • 连接测试的阶段与耗时，而不是密码或完整配置文件。

仍未解决时，可在 GitHub Issues 提交已脱敏信息。
