Chrome 代理切换器：从配置到验证

代理扩展不提供网络线路；它负责把 Chrome 指向您已经拥有和信任的代理服务器。

先理解三种模式

Direct

Chrome 直接访问网络，不使用扩展代理。排查代理故障时，这是最清晰的基准。

System

Chrome 跟随操作系统代理。此时 ProxyFox 不决定具体代理地址。

自定义配置

ProxyFox 使用您填写的协议、主机、端口和可选认证信息配置 Chrome。它只影响当前 Chrome 环境，不是系统级 VPN。

创建第一份配置

  1. 打开 ProxyFox 设置页并选择“添加配置”。
  2. 填写易识别的名称，例如“Office QA”。
  3. 选择 HTTP、HTTPS、SOCKS4 或 SOCKS5。
  4. 填写代理主机和端口；仅在代理确实要求认证时填写凭据。
  5. 如有内网或本地地址需要直连，添加白名单。
  6. 运行连接测试，确认后保存并启用。
不要在主机字段中粘贴完整 URL。主机只填写域名或 IP，协议和端口使用各自字段。

如何确认已经生效

先观察 Popup 中的当前配置，再访问您信任的测试地址。ProxyFox 的保存前测试会临时应用候选配置，显示应用耗时与网络耗时，然后恢复原设置。它不会持续监控代理健康状态。

认证代理

认证信息使用 chrome.storage.local 保存在当前 Chrome 配置文件中。扩展仅在认证挑战的代理主机和端口与当前配置严格匹配时提供凭据。本地存储不是加密保险库，不要在共享系统账户中保存敏感密码。

常见排查顺序

  1. 切换到 Direct，确认基础网络正常。
  2. 核对协议、主机和端口。
  3. 确认代理允许来自当前网络的连接。
  4. 检查认证信息是否正确。
  5. 检查白名单是否意外绕过目标域名。
  6. HTTPS 证书警告应由网络管理员处理，不要降低浏览器安全设置。
